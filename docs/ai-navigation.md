# Навигация для ИИ

Форк расширяет MCP `object` и `callers`. Основа — SQLite; формат базы совместим с исходной версией.

## Полная выдача графа

`callers(method, module, direction, depth, limit, offset)` возвращает `has_more` и `next_offset` отдельно в `callers`, `callees`, `unresolved_same_name`. Размер страницы ограничен 2000, общее количество результатов не ограничено этим числом. Повторять исходный запрос с `offset=next_offset` нужного раздела. На время обхода страниц индекс должен оставаться неизменным.

Входящие связи обходятся в ширину до depth, циклы и повторные процедуры исключаются. Исходящие `callees` — непосредственные места вызова (как в исходной версии); `depth` относится к входящему обходу. `callee_key` идентифицирует разрешённую цель. Неразрешённые вызовы не считаются доказанными зависимостями.

## Карточка объекта

По умолчанию `object` теперь включает формы и следующие разделы:

- `modules`: собственные модули;
- `metadata_in`, `metadata_out`: входящие и исходящие связи метаданных с видом связи и источником;
- `code_usages`: обращения из кода и BSL-запросов с модулем и строкой;
- `form_details`: реквизиты, элементы, события и команды собственных форм;
- `form_references`: реквизиты форм с явным типом искомого объекта;
- `subsystems`, `defined_types`, `characteristic_types`: дополнительные структурные связи.

Каждый новый раздел поддерживает limit/offset и имеет собственное продолжение. Для подробного раскрытия передавать parts с одним нужным разделом. Параметр category разделяет одноимённые объекты.

У обработчика формы возвращаются модуль и строка объявления. У элемента формы command_name — значение CommandName; оно связывает кнопку с записью команды той же формы. Адрес XML — файл и имя узла; номера строк XML не синтезируются.

## Доработка индекса

Элементы без обработчиков и самозакрытые элементы больше не теряются. Привязка элемента к команде хранится в extra_json, без изменения схемы БД.

Исправлено извлечение квалификатора у вызовов в цепочках. Литеральные ОписаниеОповещения/NotifyDescription с получателем ЭтотОбъект/ThisObject попадают в граф как `$notification$Имя`, с разрешением на метод текущего модуля. Иной получатель или вычисляемое имя не разрешаются без вывода типов.

Строки вызовов сохраняются при полной и инкрементальной индексации.

Для новых элементов форм, строк вызовов и исправленного графа необходима полная пересборка старого индекса. Новая карточка работает и со старым индексом, но не восстанавливает отсутствующие в нём данные.

## Веб-интерфейс

Левая панель по умолчанию показывает дерево метаданных: «Общие», затем основные виды в порядке Конфигуратора. Внутри разделов объекты следуют порядку `Configuration.xml/ChildObjects`, без алфавитной пересортировки. Вложенные реквизиты, табличные части, формы, команды и макеты читаются из XML объекта. Модули раскрываются в процедуры в порядке строк исходного кода. Данные загружаются при раскрытии ветки. Ввод поискового запроса временно заменяет дерево результатами; очистка строки возвращает дерево.

Для дерева нужны исходные XML по `source_path` индекса. Их недоступность отображается ошибкой. Дерево не изменяет выгрузку или индекс; HTTP `/api/metadata` только читает их.

Запуск: `gyrfalcon ui --db <индекс.db> --port 8791`, затем открыть `http://127.0.0.1:8791/`.

Главная страница показывает всю достижимую компоненту от текущего объекта, реквизита или процедуры в обоих направлениях. Ограничений числа узлов, связей и глубины обхода нет. В карту входят структурное владение, вызовы процедур и оповещения, формы и их обработчики, ссылки метаданных, запросы, поля, подписки, определяемые типы, состав подсистем и планов обмена, движения, права true/false и перехваты расширений. Структурные связи и роли могут объединять почти всю конфигурацию даже от одной процедуры: это навигационная достижимость, а не утверждение о влиянии изменения на все найденные узлы.

Данные карты читает HTTP `/api/graph?args=<JSON>` из согласованного снимка SQLite, напрямую и без постраничных лимитов MCP. Начальный узел задаётся `{kind:"object",category,name,field?}`, `{kind:"method",module,name}` или `{key}` из предыдущего ответа. Ответ содержит компактные строки `nodes`, `edges`, словари `files`, `kinds` и описания колонок. `distance` — кратчайшее расстояние от корня; `complete_in_index=true`, `truncated=false` относятся к компоненте известных индексу связей. Повторения одной пары и вида связи объединяются с числом `occurrences` и одним представительным источником; это число строк индекса, а не уникальных смысловых зависимостей. Разные виды связи между той же парой сохраняются.

Карта рисуется Canvas без внешних библиотек. Обзор показывает все узлы и связи; подписи появляются при приближении. Поиск работает по всей загруженной карте и позволяет приблизить узел, увидеть его соседей, направление и источники, открыть код, подсветить кратчайший путь от текущего узла. Двойной щелчок или «Сделать текущим» меняет корень, сохраняя загруженную компоненту; кнопка назад возвращает предыдущий контекст. Полотно перетаскивается, масштаб меняется колесом и кнопками. Списки результатов поиска и соседей листаются отдельно, не ограничивая сам граф.

По умолчанию выбрано «Все достижимые». Пользователь может явно выбрать глубину 1/2/3, направление или вид связей. При выборе узла, скрытого фильтрами, интерфейс возвращает полную карту. Кнопка «Обновить» загружает новый снимок индекса, «Отменить» прерывает ожидание ответа в браузере и сохраняет предыдущую карту. Сервер заканчивает уже начатое чтение; отмена не прерывает SQLite-запрос. Подробные карточки справа по-прежнему запрашивают страницы по 100 независимо от полной карты. Неразрешённые совпадения остаются в карточках и не превращаются в доказанные рёбра графа.

Прежняя обзорная карта доступна по `/map`. Все ресурсы встроены в бинарь. Сервер слушает только localhost. MCP stdio `find/object/callers/read` сохраняет прежний контракт; HTTP полного графа не добавляется автоматически в список инструментов подключённого ИИ.

## Границы

Это статические связи, а не гарантия всех зависимостей времени выполнения. Динамический код, произвольные получатели оповещений и полный вывод типов переменных требуют отдельных работ. Вычисляемые тексты запросов, неоднозначные псевдонимы и вычисляемые проекции не считаются разрешёнными полями. Наблюдавшиеся 4% по формам были метрикой связей на выборке объектов, а не долей разобранных файлов форм; новую полноту следует измерять отдельно.

## Второй этап: подписки, запросы, реквизиты и права

`object` по умолчанию включает `query_usages`, `field_usages`, `rights_explicit`. Все разделы постраничные и содержат файл и строку. `object(name, category, field)` показывает адресную карточку реквизита; табличная часть задаётся путём `Строки.Товар`. Дерево интерфейса открывает такую карточку при выборе реквизита.

- Подписки: прямой источник, весь вид и определяемые типы с вложениями; циклы не зацикливают раскрытие. Выдаётся адрес процедуры обработчика. Карточка самой подписки содержит `subscription_sources` и `subscription_handler`. У процедуры `platform_entrypoints` учитывает модуль, чтобы не смешивать тёзок.
- Запросы: источники ИЗ/FROM и СОЕДИНЕНИЕ/JOIN, псевдонимы, виртуальные таблицы, XML/СКД. `bsl_query_reference` и `xml_query_reference` — ссылки на тип/значение внутри запроса, они не объявляются чтением таблицы. `xml_table_source` — основная таблица динамического списка. Сложные/неоднозначные запросы могут давать только часть связей; прежний `code_usages` сохраняется отдельно.
- Реквизиты: типизированные пути форм, обращения из кода к реквизитам форм и ЭтотОбъект в модуле объекта, поля псевдонимов запросов, переходы по однозначным ссылочным реквизитам. Простые проекции связываются с полями динамических списков и СКД. Для автоматического списка прямое связывание выполняется только при явном ManualQuery=false. Агрегаты и выражения не подменяются простыми полями.
- Права: `rights_explicit` хранит явные true и false, включая элементы объекта. False не означает запрет при объединении ролей; эффективные права пользователя и ограничения доступа не вычисляются. Карточка роли включает обратный раздел `role_objects`. Старый `rights` сохраняет прежнюю семантику разрешений.

Новые таблицы SQLite: `navigation_usages` и `navigation_rights` (видны через `schema`). Нужна полная сборка индекса для их появления. Инкремент BSL обновляет связанные строки; сбой обновления помечает адресные связи неактуальными вместо выдачи старых данных. Для XML требуется полная сборка. Дополнительный проход обрабатывает основной корень выгрузки; отдельные внешние корни расширений пока не объединяются в адресном индексе.

Это навигационные связи, а не готовый анализ изменений или решение о поставке. Отсутствие связи не доказывает отсутствие динамического использования.
