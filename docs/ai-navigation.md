# Навигация для ИИ

Форк расширяет MCP `object` и `callers`. Основа — SQLite; формат базы совместим с исходной версией.

## Полная выдача графа

`callers(method, module, direction, depth, limit, offset)` возвращает `has_more` и `next_offset` отдельно в `callers`, `callees`, `unresolved_same_name`. Размер страницы ограничен 2000, общее количество результатов не ограничено этим числом. Повторять исходный запрос с `offset=next_offset` нужного раздела. На время обхода страниц индекс должен оставаться неизменным.

Входящие связи обходятся в ширину до depth, циклы и повторные процедуры исключаются. Исходящие `callees` — непосредственные места вызова (как в исходной версии); `depth` относится к входящему обходу. `callee_key` идентифицирует разрешённую цель. Неразрешённые вызовы не считаются доказанными зависимостями.

## Карточка объекта

По умолчанию `object` теперь включает формы и следующие разделы:

- `modules`: собственные модули;
- `metadata_in`, `metadata_out`: входящие и исходящие связи метаданных с видом связи и источником;
- `code_usages`: обращения из кода и BSL-запросов с модулем и строкой;
- `form_details`: реквизиты, элементы, события и команды собственных форм;
- `form_references`: реквизиты форм с явным типом искомого объекта;
- `subsystems`, `defined_types`, `characteristic_types`: дополнительные структурные связи.

Каждый новый раздел поддерживает limit/offset и имеет собственное продолжение. Для подробного раскрытия передавать parts с одним нужным разделом. Параметр category разделяет одноимённые объекты.

У обработчика формы возвращаются модуль и строка объявления. У элемента формы command_name — значение CommandName; оно связывает кнопку с записью команды той же формы. Адрес XML — файл и имя узла; номера строк XML не синтезируются.

## Доработка индекса

Элементы без обработчиков и самозакрытые элементы больше не теряются. Привязка элемента к команде хранится в extra_json, без изменения схемы БД.

Исправлено извлечение квалификатора у вызовов в цепочках. Литеральные ОписаниеОповещения/NotifyDescription с получателем ЭтотОбъект/ThisObject попадают в граф как `$notification$Имя`, с разрешением на метод текущего модуля. Иной получатель или вычисляемое имя не разрешаются без вывода типов.

Строки вызовов сохраняются при полной и инкрементальной индексации.

Для новых элементов форм, строк вызовов и исправленного графа необходима полная пересборка старого индекса. Новая карточка работает и со старым индексом, но не восстанавливает отсутствующие в нём данные.

## Веб-интерфейс

Левая панель по умолчанию показывает дерево метаданных: «Общие», затем основные виды в порядке Конфигуратора. Внутри разделов объекты следуют порядку `Configuration.xml/ChildObjects`, без алфавитной пересортировки. Вложенные реквизиты, табличные части, формы, команды и макеты читаются из XML объекта. Модули раскрываются в процедуры в порядке строк исходного кода. Данные загружаются при раскрытии ветки. Ввод поискового запроса временно заменяет дерево результатами; очистка строки возвращает дерево.

Для дерева нужны исходные XML по `source_path` индекса. Их недоступность отображается ошибкой. Дерево не изменяет выгрузку или индекс; HTTP `/api/metadata` только читает их.

Запуск: `gyrfalcon ui --db <индекс.db> --port 8791`, затем открыть `http://127.0.0.1:8791/`.

Главная страница строит направленную схему **«два уровня до текущего узла → текущий узел → два уровня после»**. Слева — источники, из которых можно дойти до корня не более чем за два перехода; справа — цели, до которых можно дойти от корня за два перехода. Отдельные цепочки сохраняют направление. Например, `Корень → Б ← В` не добавляет В на основании этого пути, а `Корень ← А → Г` не добавляет Г. Если входящих или исходящих связей нет, соответствующая сторона остаётся пустой.

HTTP `/api/graph?args=<JSON>` читает согласованный снимок SQLite. Начальный узел: `{kind:"object",category,name,field?}`, `{kind:"method",module,name}` или `{key}`. Режим фиксирован: `scope=directed_2_before_2_after`, `incoming_depth=2`, `outgoing_depth=2`. Параметр прежней глубины не меняет эти границы. Это два независимых направленных обхода, а не ненаправленный радиус двух или пяти уровней.

Ответ содержит компактные `nodes`, `edges`, словари `files`, `kinds` и описания колонок. `incoming_distance`/`outgoing_distance` — расстояния до/после корня либо null; `distance` — минимум известных направленных расстояний. Включаются рёбра, лежащие на входящем или исходящем пути длиной до двух переходов. Перекрёстные рёбра между попавшими в выборку узлами не добавляются автоматически. `complete_in_scope=true` означает полноту в выбранной схеме, `limited_by_depth`/`truncated` — наличие продолжения вне неё.

Canvas располагает узлы в пяти колонках, корень в центре. Узел, достижимый в обе стороны, показан один раз на стороне с меньшим расстоянием (при равенстве справа); оба расстояния доступны в деталях. Направление отмечено стрелками. Внутри колонок нет ограничения числа соседей. Первоначальный масштаб показывает область вокруг корня, полотно перемещается и масштабируется; «По размеру» показывает всю схему. Длинные подписи сокращаются, полное имя и источник доступны при выборе или в поиске. На высоком увеличении полотно рисует только попавшую в экран область, данные не обрезаются.

При смене текущего узла загружается его собственная схема 2+2. Предыдущий рисунок другого узла сразу очищается. Ошибка или отмена не восстанавливают его под новым заголовком; остаётся пустое полотно с сообщением и возможностью повторить загрузку. При обновлении того же узла сохранённая схема может оставаться на экране с явной пометкой. Запоздавшие ответы игнорируются, а идентификатор корня ответа проверяется перед отображением. Поиск внутри карты охватывает только её; поиск конфигурации слева доступен для любого объекта/процедуры. Фильтры видов и направлений сохраняют предел в два перехода. Выбор скрытого направлением узла возвращает оба направления; режим видов связей меняется отдельной загрузкой. Кратчайший путь подсвечивается; доступны код, источники и история переходов.

Повторы одной пары и вида связи объединяются с числом `occurrences` и одним представительным источником. Разные виды связи сохраняются. Списки справа листаются отдельно от графа. «Обновить» получает новый снимок, «Отменить» прерывает ожидание и сохраняет старую схему; сервер заканчивает начатое чтение.

Прежняя обзорная карта доступна по `/map`. Ресурсы встроены в бинарь, сервер слушает localhost. MCP stdio `find/object/callers/read` сохраняет прежний контракт. Режимы всех достижимых связей и радиуса пяти уровней заменены схемой 2 до + 2 после по уточнению пользователя.

## Границы

Это статические связи, а не гарантия всех зависимостей времени выполнения. Динамический код, произвольные получатели оповещений и полный вывод типов переменных требуют отдельных работ. Вычисляемые тексты запросов, неоднозначные псевдонимы и вычисляемые проекции не считаются разрешёнными полями. Наблюдавшиеся 4% по формам были метрикой связей на выборке объектов, а не долей разобранных файлов форм; новую полноту следует измерять отдельно.

## Второй этап: подписки, запросы, реквизиты и права

`object` по умолчанию включает `query_usages`, `field_usages`, `rights_explicit`. Все разделы постраничные и содержат файл и строку. `object(name, category, field)` показывает адресную карточку реквизита; табличная часть задаётся путём `Строки.Товар`. Дерево интерфейса открывает такую карточку при выборе реквизита.

- Подписки: прямой источник, весь вид и определяемые типы с вложениями; циклы не зацикливают раскрытие. Выдаётся адрес процедуры обработчика. Карточка самой подписки содержит `subscription_sources` и `subscription_handler`. У процедуры `platform_entrypoints` учитывает модуль, чтобы не смешивать тёзок.
- Запросы: источники ИЗ/FROM и СОЕДИНЕНИЕ/JOIN, псевдонимы, виртуальные таблицы, XML/СКД. `bsl_query_reference` и `xml_query_reference` — ссылки на тип/значение внутри запроса, они не объявляются чтением таблицы. `xml_table_source` — основная таблица динамического списка. Сложные/неоднозначные запросы могут давать только часть связей; прежний `code_usages` сохраняется отдельно.
- Реквизиты: типизированные пути форм, обращения из кода к реквизитам форм и ЭтотОбъект в модуле объекта, поля псевдонимов запросов, переходы по однозначным ссылочным реквизитам. Простые проекции связываются с полями динамических списков и СКД. Для автоматического списка прямое связывание выполняется только при явном ManualQuery=false. Агрегаты и выражения не подменяются простыми полями.
- Права: `rights_explicit` хранит явные true и false, включая элементы объекта. False не означает запрет при объединении ролей; эффективные права пользователя и ограничения доступа не вычисляются. Карточка роли включает обратный раздел `role_objects`. Старый `rights` сохраняет прежнюю семантику разрешений.

Новые таблицы SQLite: `navigation_usages` и `navigation_rights` (видны через `schema`). Нужна полная сборка индекса для их появления. Инкремент BSL обновляет связанные строки; сбой обновления помечает адресные связи неактуальными вместо выдачи старых данных. Для XML требуется полная сборка. Дополнительный проход обрабатывает основной корень выгрузки; отдельные внешние корни расширений пока не объединяются в адресном индексе.

Это навигационные связи, а не готовый анализ изменений или решение о поставке. Отсутствие связи не доказывает отсутствие динамического использования.

## Навигация: подписи, группы, объяснения и пакет для ИИ

К строкам узлов добавлены `qualified_name`, `owner_key`, `owner_label`. Владелец
сохраняется даже если сам не входит в выбранные два перехода. Короткое имя
показывается вместе с владельцем; полное имя доступно в поиске и деталях.
На полотне узлы одного владельца и вида внутри одной колонки объединяются
в раскрываемую группу. Поиск раскрывает нужную группу. Канонические узлы и
связи не удаляются; счётчик отдельно показывает число элементов на полотне.
Внешние колонки упорядочены по среднему положению связанных внутренних узлов,
чтобы уменьшить пересечения, при этом корень остаётся в центре пяти колонок.
Дополнительные внешние библиотеки отрисовки не требуются.

`relationship_mode` применяется до обхода: all, code (модули, процедуры,
вызовы, обработчики), data (запросы/поля/ссылки на менеджеры, объявленные движения),
structure (типизация и состав метаданных), forms, rights. Формы, структура и права
не выдаются за доказанное выполнение кода. `include_denied_rights=false` скрывает
явные false роли. По умолчанию они сохранены, с прежним предупреждением о том,
что невыданное право роли не является глобальным запретом пользователя.

Новый MCP `navigation` доступен all/analysis/scout и установочным ролям.
Через локальный HTTP вызывается `/api/explore?tool=navigation&args=<JSON>`:

- `mode=graph` — та же направленная схема 2+2, адреса как у `/api/graph`;
- `mode=path,from,to` — кратчайший направленный путь до двух переходов,
  вид каждой связи, все адреса источников постранично (`evidence_offset`,
  `evidence_limit`). Фрагмент — до шести строк, ограничен 1800 символами.
  При отсутствии строки отдаётся адрес объекта метаданных, без выдуманного
  номера. Источник читается только в каноническом корне проекта. Файл может
  измениться после индексации: это явно указано в контексте;
- `mode=context,key,max_chars=16000,limit=12,offset=0` — корень, связи,
  источники/фрагменты, неопределённости и счётчики пропущенного. Код/данные
  приоритетнее структуры/прав. `has_more/next_offset` позволяют продолжить
  с теми же параметрами. Бюджет — символы компактного JSON, не токены модели;
- `mode=search,query,kind,limit` — существующий гибридный ранжировщик имени,
  синонимов и токенов с восстановлением точных адресов кандидатов. Разные
  модули одноимённых методов не смешиваются. Если нет словаря эмбеддингов,
  `search_mode=lexical_and_hashed_tokens` и note сообщают об этом. Это не
  нейросетевое понимание произвольного текста. Внешняя модель не вызывается.

В интерфейсе: «Почему связаны?» в деталях узла открывает цепочку, источники,
фрагменты и продолжение списка источников. «Контекст для ИИ» показывает JSON,
позволяет скопировать его и перейти к следующей странице. Текущее подключение
MCP в стороннем клиенте автоматически не меняется: новый инструмент доступен
при запуске MCP-сервера этой сборки.

Резолвер дополнительно распознаёт литеральные цепочки БСП вида
`ОбщегоНазначения.ОбщийМодуль("Имя").Метод()`. Вычисляемые имена, произвольные
фабрики и общий вывод типов переменных этим правилом не покрываются.
Для появления новых разрешённых вызовов нужен новый индекс или обновление
затронутых BSL-модулей. Старые БД остаются совместимы.
