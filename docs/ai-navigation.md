# Навигация для ИИ

Форк расширяет MCP `object` и `callers`. Основа — SQLite; формат базы совместим с исходной версией.

## Полная выдача графа

`callers(method, module, direction, depth, limit, offset)` возвращает `has_more` и `next_offset` отдельно в `callers`, `callees`, `unresolved_same_name`. Размер страницы ограничен 2000, общее количество результатов не ограничено этим числом. Повторять исходный запрос с `offset=next_offset` нужного раздела. На время обхода страниц индекс должен оставаться неизменным.

Входящие связи обходятся в ширину до depth, циклы и повторные процедуры исключаются. Исходящие `callees` — непосредственные места вызова (как в исходной версии); `depth` относится к входящему обходу. `callee_key` идентифицирует разрешённую цель. Неразрешённые вызовы не считаются доказанными зависимостями.

## Карточка объекта

По умолчанию `object` теперь включает формы и следующие разделы:

- `modules`: собственные модули;
- `metadata_in`, `metadata_out`: входящие и исходящие связи метаданных с видом связи и источником;
- `code_usages`: обращения из кода и BSL-запросов с модулем и строкой;
- `form_details`: реквизиты, элементы, события и команды собственных форм;
- `form_references`: реквизиты форм с явным типом искомого объекта;
- `subsystems`, `defined_types`, `characteristic_types`: дополнительные структурные связи.

Каждый новый раздел поддерживает limit/offset и имеет собственное продолжение. Для подробного раскрытия передавать parts с одним нужным разделом. Параметр category разделяет одноимённые объекты.

У обработчика формы возвращаются модуль и строка объявления. У элемента формы command_name — значение CommandName; оно связывает кнопку с записью команды той же формы. Адрес XML — файл и имя узла; номера строк XML не синтезируются.

## Доработка индекса

Элементы без обработчиков и самозакрытые элементы больше не теряются. Привязка элемента к команде хранится в extra_json, без изменения схемы БД.

Исправлено извлечение квалификатора у вызовов в цепочках. Литеральные ОписаниеОповещения/NotifyDescription с получателем ЭтотОбъект/ThisObject попадают в граф как `$notification$Имя`, с разрешением на метод текущего модуля. Иной получатель или вычисляемое имя не разрешаются без вывода типов.

Строки вызовов сохраняются при полной и инкрементальной индексации.

Для новых элементов форм, строк вызовов и исправленного графа необходима полная пересборка старого индекса. Новая карточка работает и со старым индексом, но не восстанавливает отсутствующие в нём данные.

## Веб-интерфейс

Левая панель по умолчанию показывает дерево метаданных: «Общие», затем основные виды в порядке Конфигуратора. Внутри разделов объекты следуют порядку `Configuration.xml/ChildObjects`, без алфавитной пересортировки. Вложенные реквизиты, табличные части, формы, команды и макеты читаются из XML объекта. Модули раскрываются в процедуры в порядке строк исходного кода. Данные загружаются при раскрытии ветки. Ввод поискового запроса временно заменяет дерево результатами; очистка строки возвращает дерево.

Для дерева нужны исходные XML по `source_path` индекса. Их недоступность отображается ошибкой. Дерево не изменяет выгрузку или индекс; HTTP `/api/metadata` только читает их.

Запуск: `gyrfalcon ui --db <индекс.db> --port 8791`, затем открыть `http://127.0.0.1:8791/`.

Главная страница — поиск объектов и процедур по имени и синониму, граф прямых входящих/исходящих связей, фильтр вида связей, панель источников и просмотр кода процедуры. Двойной щелчок по разрешённому узлу открывает его связи; кнопка назад возвращает предыдущий контекст. Полотно и узлы перетаскиваются, масштаб меняется колесом и кнопками.

Для читаемости граф показывает не более шести входящих и шести исходящих соседей из загруженных данных. Число оставшихся соседей указано над графом. Списки справа содержат все загруженные записи; кнопка «Загрузить ещё 100» запрашивает следующую страницу категории. Неразрешённые совпадения доступны отдельным списком. Вызовы платформы помечены отдельно.

Прежняя карта конфигурации доступна по `/map`. Все ресурсы встроены в бинарь, внешние библиотеки не нужны. HTTP API допускает только find/object/callers/read; сервер слушает только localhost.

## Границы

Это статические связи, а не гарантия всех зависимостей времени выполнения. Динамический код, вывод типов переменных, произвольные получатели оповещений, дополнительные XML/СКД-запросы и подписки на весь вид требуют отдельных работ. Наблюдавшиеся 4% по формам были метрикой связей на выборке объектов, а не долей разобранных файлов форм; новую полноту следует измерять отдельно.
